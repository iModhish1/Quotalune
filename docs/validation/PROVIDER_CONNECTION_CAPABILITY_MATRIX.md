# Provider connection capabilities — Wave 3

Inventory: **70** current `ProviderId::all()` entries. The JSON is generated by `quotalis_core::connection_capabilities::capability_matrix_json`; its equality test detects drift. No historical provider count controls the UI.

## Evidence boundaries

- Methods are derived from actual key/token support, browser domains **and a declared web transport**, local-session readers and the CLI dependency table. A domain alone does not make cookie import usable. They are not a claim that a real account was authenticated during this work.
- Fixture coverage means method rendering and synthetic connection-state classification. It does not establish browser decryption, account permissions or a real sign-in. Live verification: **0**.
- Schema 2 separates reporting evidence requirements from connection methods. Quota rows, reset times and plans require inspection of the verified provider response; monetary observations require the shared Spend/Balance/Credits classifier. Legacy optimistic account booleans are not reporting evidence. Successful verification returns actual quota-row counts, valid reset presence and a classified monetary kind when available; it never promises a field exists for every adapter or account.
- Five curated npm/winget package identifiers are documented; **automated installation is disabled for every dependency** until package-manager execution has trusted provenance. Instructions remain available.
- CLI execution accepts protected known installation roots only. User npm folders, PATH shims and arbitrary filenames are rejected. Unsupported install layouts use manual instructions.
- Local-session readers may contact a provider API after reading application credentials. They are not an offline-only or account-wide activity promise.
- Deprecated providers stay explicitly deprecated. No claim of their service availability is made.

## Source ownership

`ProviderId::cookie_domain`, `settings::get_api_key_providers`, `TokenAccountSupport`, `profiles::account_capabilities`, `token_periods::token_source`, `instantiate_provider`, and the eight-entry CLI dependency catalog remain the sources. The UI consumes one serialized model. API-key DTOs route to the store the adapter reads, including providers outside the older 13-key settings list.

## Authentication terminology

GitHub Copilot uses the existing GitHub device flow. No Quotalis-managed browser authorization-code callback/PKCE server exists. Codex, Claude, Kiro and Vertex sign-in reuse the CLI supervisor; only trusted executable layouts run. Other CLI integrations provide manual sign-in instructions. The UI does not advertise invented OAuth.
