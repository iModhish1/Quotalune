# Quotalis metric registry audit

**Audited source baseline:** `ef0872f3d52243462e1a6513622f56f00c706919`, with the
working tree consulted for in-flight Wave 2–4 registry work on 2026-09-09.
This is a source audit, not a claim that every source is populated, tested in
the current environment, or comparable to another provider.

## Reading the inventory

- `current` means the latest provider-cache observation. `historical` means
  local persisted history or a local-log scan. It does **not** mean a provider
  invoice or complete account history.
- A **physical window** is one primary, secondary, model-specific, tertiary,
  or named-extra quota window. Percentage denominators are provider-window
  specific, so percentage values are never summed into a cross-provider total.
- `available` below describes the code gate, rather than promising live data.
  `—` means the metric has no reset or comparison operation.
- `CostSnapshot.used` is not independently self-describing at the bridge
  boundary. Dashboard history uses `classify_monetary_observation` to attach
  quantity and measurement kind; Usage & Spend and the provider-detail bridge
  still receive the older shape.

## Source-backed correctness gaps and integration risks

1. **Fixed in this wave:** `get_daily_cost_history` initialized a zero-filled
   calendar before falling through unsupported IDs. The settings chart supports
   `openai`, so it could render a fabricated 30-day `$0` history. The helper
   now returns an empty series for unsupported IDs before scanning, with focused
   regression assertions for `openai` and an unknown ID.

2. **Fixed in this wave: Usage & Spend share-card provenance.**
   `UsageSpendTab.tsx::renderSharePng` always captions the export “local
   estimates,” while `build_usage_spend_summary` can include Cursor local cache
   amounts and provider-reported snapshots. The rows do retain a source string,
   but the export-level claim was broader than the source evidence. The caption now says source-specific readings.

3. **The bridge still needs a surface-wide monetary contract.** Dashboard
   history has `quantityKind`, `measurementKind`, currency, origin, and
   availability in `CostContract`. `UsageSpendRow`, `CostSnapshotBridge`, and
   `DailyCostPoint` do not carry the equivalent fields. Current audited
   `cached_spend` sources are not therefore claimed wrong: the source classifier
   documents Cursor and the listed provider paths as cumulative Spend. The gap
   is that downstream surfaces cannot prove that contract per row/point or keep
   it if adapters evolve.

4. **Historical and live freshness are different facts.** Dashboard live cards
   derive freshness from `updatedAt` and the configured cadence; dashboard
   history exposes range coverage/sample timestamps. The legacy OpenAI credits
   and service-breakdown DTOs export no cache timestamp, so their chart cannot
   report a freshness state.

5. **Current quota values use intentionally different selections.** The
   provider instrument uses the first valid physical window, while highest-use
   KPIs, alerts, and operations use the maximum valid physical window. Both are
   source-backed but have different meanings and must remain separate registry
   IDs/labels.

## Wave 2–4 review closure

The typed registry is `src/lib/analytics/metricRegistry.ts`. Trend Intelligence renders observed start/end/change, mean, minimum and peak. Mean selects the latest observation per bucket, preventing reset-heavy buckets from gaining extra weight. Conflicting duplicate capture counts invalidate a series independent of input order. Unknown/legacy identities remain explicitly unknown; observed accounts receive distinct local ordinals without exposing account IDs. A fresh read-only review independently reproduced all three repairs. Projection remains unsupported without a defensible workload assumption.
